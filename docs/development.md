# 开发基线

项目名为 **回放尖塔 / Replay the Spire**，独立仓库使用 GPL-3.0-only。首轮开发以单人录制、原生回放、统计、直播贴图集与有声 MP4 为交付范围。

## 回放链路

- 录制器监听游戏动作队列、战斗历史、房间选择和原生战斗记录写入。每局保留游戏构建、模组指纹、角色、种子以及连续的房间访问序号。每次重新进入都保留一个访问节点。
- 楼层入口保存原生随机数状态和对局检查点。原生战斗数据决定动作、目标和嵌套选择，以游戏提供的状态校验比较重播与原局。新格式须能区分已校验、缺少校验和出现偏差。
- 观看时使用独立的内存存档和游戏自带的表现层。跳转先恢复入口，再推进至指定节点。控制台、回放库和导出器共用同一条播放路径。事件选牌和商店删牌沿用原生选牌界面，支持在候选牌出现后暂停、逐步观看和重新定位。水晶球保存每次选中的工具和格子，并核对初始棋盘及结算时的棋盘指纹。
- 操作用时只计算可以操作且游戏有焦点的时段。录制热路径只写事件和检查点。图像、音轨和编码都在玩家选择导出后生成。
- 本地回放库以房间为单位写入。完成的单人对局自动导出 ZIP 容器格式的 `.spireplay`。回放库在后台读取对局索引，玩家可在加载过程中关闭窗口。版本和模组环境不同仍能查看记录。格式演进保留已有归档的阅读能力。

## 开发与提交

每项改动独立提交，使用 Conventional Commits，如 `feat(playback): restore room-entry checkpoints`、`fix(media): restore export audio levels`。原生接口变更须分别编译两个目标并测试。测试前确认 Steam 已隔离，使用测试用用户目录与私有游戏副本。游戏数据、反编译内容、原生录像和玩家存档保留在本地。

`src/Capture` 负责录制，`src/Storage` 管理房间、交换格式和贴文，`src/Playback` 负责沙箱与游戏重演，`src/Interface` 提供入口、控制和导出流程，`src/Media` 处理视频与声音。`tests/Storage` 可在无游戏 SDK 的 CI 运行。原生用例和硬件 A/B 测量分别见 `tests/NativeHarness` 和 `tests/Performance`。

## 后续迭代

优先收集不同角色、事件、模组组合与低配置机器的可重复对局。练习分支需要在独立存档里记录分歧点和新输入；多人回放还需要跨玩家输入排序、同步与多人存档隔离测试。
